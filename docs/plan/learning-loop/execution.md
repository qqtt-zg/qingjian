# 学习闭环：执行契约、排程与模型请求

本文件是 [学习闭环总览](../learning-loop.md) 的**第四到七章**。章节号在总览里连续编号，跨文件引用按「§几」写。
## 四、执行与迁移契约必须先落定

### 4.1 计划结构与旧数据保留

现有 `study_plans.day UNIQUE` 和统一LEARN/PRACTICE/EXAM阶段不能直接承载按词编排、多轮、分环节credit。阶段0即定义以下迁移，阶段1才启用新执行器：

| 对象 | 新契约 |
| --- | --- |
| `study_plans` | 重建时原样保留旧ID/字段/记录；去掉day单列唯一，增加round_no、format_version、status、预算快照、偏好修订、规则版本及修订号；`UNIQUE(day, round_no)` |
| `study_items` | 保留旧字段；增加reason_code/reason_text和稳定条目键 |
| `study_item_stages` | 稳定stage_key、所属条目、顺序、dimension、题型/题目快照、credit、状态、草稿、辅助、结果事件键、active_ms及测时有效性 |
| `plan_revisions` | 保存修改前后的预算/条目、用户约束、接受/拒绝操作及理由 |
| 学习偏好 | 值实际变化时递增preferences_revision；计划保存当时修订和分钟数 |
| 用户覆盖 | 按词和维度保存手动声明、有效期及解除依据，与真实成绩分开 |

不把旧计划伪装为已执行的新环节：`format_version=1`继续原执行/恢复路径，新计划为2。旧计划没有credit或测时的字段为未知，不参与新的预算加速推断；已有未完成计划优先继续，未经用户操作不被新计划覆盖。

旧记录迁移为round_no=0，status不替代其原phase；新记录按status恢复。首页、Agent及当前计划查询统一按format_version派发，不能继续用旧的 `phase!='DONE'` 将所有新格式计划误判为未完成。事务检查所有格式的活动计划，防止两个入口各建一轮。

迁移保留关联ID、题目快照、答案、录音评分、草稿及用户指令。新表加入清空、epoch检查、导出备份和电脑端备份白名单，覆盖安装不能漏备份。

### 4.2 状态、幂等与恢复

- 基线预览是只读结果，不写next_due。用户开始后事务提交为READY；随后为RUNNING/PAUSED/DONE/ABANDONED。
- 返回、切换标签、旋转和进程退出都是暂停，不能自动记为放弃。放弃须明确操作；跨日先提供继续或结束旧轮，再安排新轮。
- 环节状态为pending/done/skipped；部分完成由环节组合得出，不另造一次成绩。
- 固定stage_key去重：草稿可改，答案只提交一次；结果事件与进度同事务写入，退出重进不重复记分或增加credit。
- 开始时检查epoch、偏好、来源/能力快照修订和未完成计划；重复点击返回已有计划。修订带expected_revision，旧响应不得覆盖新指令。
- 同日默认计划只有一轮；明确“再来一轮”才分配下一个round_no。默认安排最多10项；加练另显预算，每轮也最多10项，不被自适应算法当作系统自动加量。
- 一个词在一轮内最多一项、两个环节；默认轮不重复当天已完成词。用户明确指定复练可例外，但同日复练不增加独立成功日。
- 模型修订只改未开始的环节，不删除已完成结果；每次修改保存修订历史及当时分母，不能事后删掉错题抬高完成率。

## 五、本机排程、离线执行与反馈

### 5.1 ContextPack与单一校验器

新增 `learning/context/Pack.kt`：本机先组成不可变快照，包含日期、epoch、偏好修订、预算、到期/薄弱/新词/巩固候选、材料可用性和真实分项统计。再由 `PlanBuilder`排基线，向模型传同一快照及baseline。

答疑工具留给AI老师；每日计划不再调用自由查询工具。包中只含有界候选和需要的统计，不全量倾倒历史。自评偏差在本机按同词、同维度、可比记录计算；如发送给模型必须在包中明确标记为统计数据，不能又声称“只显示不发送”。

用户约束先合并进本机预算，例如“只做一题”限制题目环节数；再排基线和处理模型修订。自然语言有歧义时用明确的本机选项确认范围，不让模型输出自动放宽约束。

### 5.2 预算与环节成本

1 credit = 30秒的计划成本，不是实测耗时。`usable=floor(minutes×2×0.9×factor)`；用户硬限制可进一步收紧，不被factor放宽。

| 环节 | credit | 有效完成 |
| --- | --- | --- |
| LEARN资料学习 | 2 | 用户明确完成阅读，不算答对 |
| 新词的一道基础练习 | 1 | 实际提交；该词学+练合计3 |
| 回忆+自评REVIEW | 1 | 保存自评，不算独立正确 |
| 薄弱练习 | 2 | 作答及查看解析各1，分环节留痕 |
| 保温练习 | 1 | 实际提交 |
| 跟读自评 | 2 | 合规录音1、回放后自评1；不自动上传评测 |

先按词合并候选维度，按最需要的能力选择不超过两个环节。计划成本是环节成本之和，不能用池名固定加1/2/3来代替真正环节，也不能覆盖同一词后重复扣费。

- 到期预留目标为 `ceil(usable×0.3)`，上限为 `floor(usable×0.6)`，均按真实到期环节credit计算。
- “下限”是在候选和其他约束允许时必须达到的可行目标；资料不足、预算过小或用户明确限制时取可行值并写原因，不能为凑配额制造任务。
- 新词上限为 `min(偏好新词数, floor(usable/3), 8)`；入门再乘0.8向下取整，有预算时最多下调到1。
- 单轮最多10项；默认轮还扣除当天默认安排的已消耗额度。手动加练作为单独轮次显示。
- 优先保留到期目标，接着处理薄弱、新词，最后用巩固或更多到期任务补余量；到期部分始终不越60%上限。
- 不使用“先占满到期上限，再无条件加新词”的旧示例。

### 5.3 候选、可执行性与难度

| 池 | 条件 | 稳定排序 |
| --- | --- | --- |
| 到期 | 有真实依据且effective_due已到 | 逾期天数降序、状态、last_at、word_id |
| 薄弱 | learning/shaky且近期至少两次有效错误，未被到期池处理 | 带时效权重错误数、辅助次数、word_id |
| 新词 | 手机未验证；有可执行的资料 | 电脑常见分、短词优先、word_id |
| 巩固 | solid且7天内到期，其他池未选 | effective_due、word_id |

多个维度归到同一词后，再决定训练环节；遇到资料缺失先做本机降级，而不是必须联网。

全维度unknown进入新词流程；仅某个维度unknown不把已有词重新算作新词。其余维度按逾期程度、learning优先于shaky、有效错误数排序；再以固定的spelling/listening/meaning/pronunciation顺序打破平局。维度合并后仍最多两个环节，不能依赖Map遍历顺序决定练什么。

| 能力/缺口 | 可执行环节 |
| --- | --- |
| 全unknown | 有可靠中文笔记时LEARN，再做有效练习；选择题缺少干扰项时仅学习/自评 |
| meaning薄弱 | 学习或词义/英文选词；选项必须足够且无歧义 |
| spelling薄弱 | 盲写，隐藏英文资料，辅助单独记录 |
| listening薄弱 | 可用离线英文TTS播放，遮住答案；音频不可用时改为明确的其他维度，不伪造听辨成绩 |
| pronunciation薄弱 | 跟读、自评；用户主动选择后才调用讯飞 |
| solid到期 | 回忆与自评，必要时独立验证 |
| 无例句/无中文笔记 | 不生成缺资料的题；可少排，或单独准备资料 |

不得把中文origin_text/example直接当英文填空材料。一词冷启动不能强行调用需要多个干扰词的Builder；没有有效题时不写答题成绩。

短词优先、每日至少一半新词不长于8字符；形近词和同前缀词限制沿用原方向。均在候选材料检查之后处理，词不足就少排，不伪造干扰项。连续三日仍薄弱时换可用维度或减少频次，不把换题型当作能力恢复。

### 5.4 构建骨架与修订

以下是流程伪代码；所有插入都通过同一个 `PlanConstraints`，模型修订也调用它，不允许各池自行操作Map和累计预算。

```text
snapshot = capture(today, epoch, preferencesRevision, desktopRevision, modelRevision)
limits = resolveBudget(snapshot, userConstraints)
candidates = normalizeByWord(snapshot)
candidates = chooseExecutableStages(candidates, limits)
ordered = reserveDueTargetThenWeakFreshAndFill(candidates, limits)

picked = empty immutable plan
for proposal in ordered:
    candidate = mergeOrAppendStages(picked, proposal)
    if PlanConstraints.accept(candidate, limits):
        picked = candidate

validate whole plan:
    unique words; max 2 stages per word; max 10 items
    sum(stage.credit) <= usable
    feasible due target; due cap; new-word cap
    material availability; question limit; stage dependencies
return picked with local reasons and deferred counts
```

`mergeOrAppendStages`显式合并维度或拒绝重复，credit每次从最终环节求和，不累加旧值。第一次可行性计算与最终验证采用同一候选快照及规则，无法满足目标时少排并记录约束原因。

模型只返回drop/swap/reorder/add操作，不返回任意新成绩或完整替换列表。逐条基于最新候选计划校验，拒绝项保留理由；swap作为一个操作原子检查。reorder必须精确覆盖当时剩余条目，不能引用已删词或重复ID。

“少做”也要满足用户约束和可行到期目标；若用户明确减少范围，则先重算目标，不能用旧到期下限拒绝用户指令。减到0应转为用户明确结束本轮，不伪称完成。

新鲜数据仅有1～5词时最多3个新词；只有电脑数据时最多3词；6～20词时新词最多2个。全部solid且无到期/新词时可为空计划，显示今天可休息。回来后有旧计划先恢复；结束旧轮后可排最多3个热身词。

### 5.5 真实反馈与完成率

| 行为 | 留痕与影响 |
| --- | --- |
| 提交题目 | 唯一结果事件；按正误/辅助更新对应能力 |
| 完成资料或自评 | 完成对应环节credit，不产生独立答对 |
| 跳过 | skipped，不算attempt；记当日避让 |
| 暂停/退出 | 保存草稿与已完成环节，不记放弃或错误 |
| 明确放弃 | abandoned，保留完成部分；未做环节不制造失败成绩 |

完成率 = 已完成环节credit / 当时已分配credit。学完2credit但没有完成1credit练习，显示2/3；只在页面停留不自动获得完成credit。修改计划保留每次分母，不删除跳过记录。

连续两日主动跳过同一词，下一次降优先级或换可用维度；连续三次则暂停本周自动安排。用户主动指定复练不受此限制，跳过不降低能力分。

### 5.6 自适应预算与测时

分别存 `planned_credit/done_credit` 和实测 `active_ms`；不能把credit当作“做得快”的时间证据。

- active_ms仅累计前台正在执行环节的单调时钟时长，暂停/后台时间不计；旋转不能重复累计。
- 测时中断、旧计划无测时或进程死亡造成区间不可恢复时，标记measurement_valid=false，不凭空补时长。
- factor只看当前preferences_revision下最近三个已结束的默认计划日，排除加练及明确限制题数的轮次；同日多轮不冒充三天。
- 跳过与明确放弃保留完成率；还在暂停的计划暂不当作一个失败日。没有计划或planned_credit=0的日期不进入分母。
- 偏好实际变化就递增revision，历史样本不匹配时返回1.0；不是声称旧历史会因今日分钟数变化而自动改变。

```text
eligible = endedDefaultDays matching currentPreferencesRevision
last3 = latest 3 distinct days with planned_credit > 0
if fewer than 3 days: factor = 1.0
else if sum(done_credit) / sum(planned_credit) < 0.5: factor = 0.8
else if all fully completed, all measurement_valid,
        and each active_ms < planned_credit * 30_000 * 0.6:
    factor = 1.1
else: factor = 1.0
```

这是每次派生的0.8/1.0/1.1，不存累计budget_factor，不逐日复乘。界面只显示“最近完成得少，今天少安排一点”等简短理由。

## 六、模型请求、理由与成本

### 6.1 替换执行路径，而非只改工具名

现有每日链路先调用get_study_context，再提交提案，最后收尾，最多3次请求；每日Job没有答疑Session那一次自动摘要。不能用“现在3次+摘要1次”作为每日计划的成本基线。

新每日入口仍使用Koog编排，但与现有答疑传输分开配置：

1. 本机直接组装ContextPack和baseline作为数据输入，不再先请求模型读取事实。
2. 首次请求只开放prepare_study_plan，返回简短解释和可选修订；收到有效提案即结束本次图，不再追加一次“工具执行后收尾”请求。
3. 如确有材料缺口且用户允许联网，再用一次prepare_word_materials请求；每批最多3词。其他词本轮降级或延后。
4. request budget从本次点击开始共用，覆盖所有模型请求、解释、修订和资料生成；工具执行次数不等于HTTP请求数。取消和失败均计入已发出的请求。
5. 第二次失败保留已经可执行的本机计划与原有资料，不为了补完解释或材料静默调用第三次。
6. **阶段1（纯本机排程）的每日计划请求数为 0**：新计划CREATE直接走本机校验与提交，不经模型。答疑入口（`TutorActivity`）与「补全中文笔记」保持各自现有预算，**不计入每日计划预算**；只有用户在计划里显式问老师时才走答疑通道。阶段1 与阶段2 的预算分别记账，别把答疑的消耗算到每日排程头上。

现有Transport中factsFirst、三轮上限及Runner收尾路径都需按每日模式改造；答疑、笔记和手动全量分析保留各自边界，不能顺带降低取消或修订保护。

批量资料工具需要新增明确的词ID数组、每词完整资料及资料修订校验；现有单词工具不能仅靠提示词就算支持三词。每个词的资料整包原子保存，非法或陈旧词条延后；工具结果不需要再请求模型才能向用户展示。无有效提案的普通文字回复消耗一次请求后退回本机计划，不隐式追问。

| 场景 | 本次每日安排的HTTP请求数 |
| --- | --- |
| 本机数据足够，无模型参与 | 0 |
| 用户要求解释/修订，或需要语义辅助 | 1 |
| 还需要一批资料，最多3词 | 再加1，总数最多2 |
| 网络失败或已用完预算 | 保留本机结果；重试须由用户另行发起 |

新请求仍使用手机AI配置。资料和输入包是不可信数据，不作为系统指令或执行授权；模型不能写能力投影、成绩、计时和复习日期。不要承诺请求减半等百分比收益，按ai_usage的真实调用数、token和延迟验证。

### 6.2 本地理由与效果验证

所有条目保存reason_code/reason_text；即使完全断网，仍能解释到期、薄弱、新词、材料不足和顺延原因。顶部理由折叠展开，不另加一整排工具按钮。

模型介入时记录输入快照修订、提出/接受/拒绝的操作及理由。采纳率与模型用量仅用于观察，同时看后续完成率和独立作答结果，不能只凭采纳率判定教学效果。

维持学习、词库、AI老师、我的四入口；首页突出今日任务与继续学习，词卡内完成拼写、跟读和追问。长解释和高级选项折叠，当前连接状态及扫码仍在标题右侧。零词、离线、材料不足、生成中、失败、暂停和全部完成各有一个明确主行动，320dp和软键盘下检查。

## 七、电脑常见词排序

第一版不用应用名也能排序：

```text
base_score =
    0.50 * min(log2(1 + committed) / 6, 1)
  + 0.30 * recency(last_date, today, 30_days)
  + 0.20 * available_phone_error_rate
```

未知日期和手机错误率标为未知，相关项不伪造测量；在可用权重上归一化。同分以word_id升序。硬条件是来源可靠、计数合法、材料可执行；新手机手动词不受电脑committed下限限制。

电脑常见词候选可用committed至少3且30日内接触作筛选；不把它称为真实英文写作频率。desktop_known用于减低未验证词的扩展优先级，手机真实薄弱时不能因其被排除。

应用聚合接入后，另以显式版本升级排序规则；保留聚合覆盖时间与未知标记。不能因应用缺失而把全部工作词降成0分，也不根据软件名称推断行业或公司。
