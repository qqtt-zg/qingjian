# 青简学习流程交互草案

状态：用户已确认学习方向与交互，并要求继续接入真实 Agent。0.2.18-dev 原生实现与执行边界见 [每日学习 Agent](mobile-study-agent.md)。本文件与 [可点击原型](mobile-study-flow.html) 记录交互参考，原型中的固定演示数据不进入 App。

## 体验目标

沿用已确认的米白与青绿、三个底部入口及标题连接区。首页围绕唯一的「开始／继续今天学习」，不将新词、复习、考试分别做成需要用户自行拼凑的功能入口。进入任务后底部固定当前主行动；内容独立滚动，返回、刷新保留位置。

原型只使用两条新词、两道带提示练习、三道独立小测和两条旧词复习。数量及内容均为演示，不代表正式学习配额。阶段快速跳转仅供评审，不能自动生成作答或掌握记录。

## 每一步的交互

1. 今日：展示轻量安排、当前步骤及完成进度，一个主按钮继续。
2. 认识：每屏一个词、一个搭配与短句；词和整句分别可听。看过不算掌握。
3. 练习：选择即反馈，允许提示；声音按钮独立于作答。提交后仍可听选项，底部继续下一题。
4. 小测：先说明范围和规则，一屏一题，选择后主动点下一题。全部完成后统一揭晓答案。听辨题允许重播；音频不可用可用文字辅助，并单独记录。
5. 复习：先回忆再显示答案，选择是否想起；自评不并入客观测验。
6. 小结：按真实操作区分接触新词、自评词、独立答对和使用辅助的题。未测显示「未测」；不以一次正确标记掌握。下一步建议来自本轮错题和自评，正式复习日期仍需单独调度实现。

疑问入口带当前词进入老师页，保留返回学习入口；不需要重新搜索或复制问题。原型仅显示预置讲解，不调用真实 API。

## 数据与执行约束

- 一轮计划、任务与作答分别有稳定标识；原生版本需要 SQLite 保存，不依赖视图位置作为完成依据。
- 学习浏览、练习提示、独立测验与自评分别记录。独立正确依据题目答案及本次辅助状态；听力重播次数独立保留，不凭模型猜测。
- 回到同一结果页不能再计分；练习和小测的待提交选择、中途退出位置需要保留。
- 计划、到期复习与结果查询作为下一阶段工具；真实成绩仍由应用根据用户提交写入，AI 不直接填写正确率或完成情况。
- 初始水平目前采用原有偏好，轻量定位测评另行设计。拼写输入、开放表达和口语自动评分未包含在这份界面原型中。

## 原型边界

演示进度保存在此浏览器的 `qingjian.study-flow.preview.v1`，重置只影响该键。没有真实账号、配对、相机、AI 请求、到期调度或资料推送。浏览器朗读与 Android 内置音色不同；网页播放失败应显示说明，不阻止继续浏览。

验证重点：完整流程、退出与刷新续做、重复进入结果不增计数、提示/独立成绩/自评分离、辅助标记、带词问答与返回，以及 320px 窄屏主行动可见。
