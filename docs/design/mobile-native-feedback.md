# Android AI 学习交互：0.2.17-dev

按照 [HTML 原型](mobile-ai-feedback.html) 实现原生交互，继续采用 Kotlin Views、Koog 1.3.0、系统 SQLite 和原有 sherpa-onnx 音色，不增加运行依赖。

## 标题与会话

三个主页使用 `MainHeader`，简短连接状态与扫码在同一水平位置；设置仅在学习首页的状态左侧。重连与停止移到状态打开的 `ConnectionPanel`，不挤占标题宽度；设置、复习和词条答疑子页不重复放连接区。会话列表由左侧 Dialog 展开，提供当前话题与新建；请求忙碌时不切换话题。

复用 `ConnectionControls` 扫码和接收控制。更换图标不更改配对协议、后台接收策略或远程音色配置。

布局与启动图标详见 [标题栏与图标](mobile-header.md)，原型见 [HTML 预览](mobile-header-preview.html)。

## 自动操作与回执

Koog 的五项工具仍为白名单。正式答疑使用自动模式，数据库里的原问题是授权来源；模型不能通过工具参数声明权限。

- 词卡自动保存为待学习，已有非空笔记保留。每次请求新增量不超过学习偏好的新词目标，最高八个；这是单次请求上限，没有每日调度或每日已完成计数。
- `IntentPolicy` 仅允许原问题明确要求且未否定的朗读或练习。没有明确要求时返回 `needs_user_request`，不创建待确认步骤；老师可继续解释或询问意图。
- 练习工具准备不可变题目快照，UI 直接在相关回答后呈现；实际点选或拼写提交后才计分，题号保证旋转不重复计分。
- 朗读工具先排队，当前请求回答成功、AI 页位于前台且未取消时提交一次 `ReceiverService` 请求。取消、失败、旧页面恢复和进程重启都不能自动补播历史待执行项。结果回执只说已提交，播放器的完成记录独立处理。
- 老版本未执行的草稿保留手动继续入口，升级时不会批量执行历史操作。提交失败后保留手动重试，不因重新渲染循环重试。

操作回执与原问题/回答关联。请求中途取消时，先前已经完成的写入不会隐瞒或伪称回滚；新增词卡仍可尝试撤销。

## 撤销与数据升级

SQLite v5 保留所有 v1～v4 数据，给操作增加 `automatic`、`created_word` 和 `word_snapshot`。词条 ID 改用 AUTOINCREMENT，避免删除新增词后复用旧 ID 接收晚到结果。

撤销只接受这项操作实际创建的词，且该词快照未改变，没有练习、录音、词条会话或其他已应用操作引用。收到新内容、完整播放、自评、修改笔记或开始关联学习后，撤销保留词条并说明原因。其他已应用练习对该词有引用时也保留。原有词永远不能通过新增回执删除；未使用的新词删除后，最近学习指针同步清除。清空会话仍保留已应用的词卡资料。

## 题型与选项朗读

原「词义选择」「中文拼写」保留。新增「英文选词」使用中文笔记提示、英文选项；相同笔记对应多个词时不为该目标出英文选词题，减少歧义。新增「搭配填空」基于已保存词卡例句，只在原词精确出现一次时挖空；答案以原词卡的词为准，不把其他表达一概判为语法错误。

英文选项右侧是独立 Button，答案按钮禁用后喇叭仍可用。`PreviewSpeech` 复用 `SpeechPlayer` 的音色、响度处理、音量和语速；新请求替换旧试听，离开页面关闭播放器，原生请求编号隔离迟到回调。试听不收录新词、不写词汇播放计数，也不影响作答结果；不使用浏览器或系统 TTS，不打开麦克风。

Standalone 和对话内练习均可查看本题反馈、继续搭配或重新巩固；搭配例句不足时提示补资料。完成小结只统计本轮真实题目，不等于已掌握、每日任务已完成或发音已评分。

## 状态与上下文

工具调用按实际能力显示查词、读取记录、整理词卡、准备练习或朗读阶段，不按定时器模拟百分比。请求失败保留问题和受控提示，用户手动重试。当前请求的偏好、词条、摘要和相关记录以可展开的中文说明展示，隐藏内部 ID；该说明随本次保留的 Session 存活，旧会话重新打开时不假装重新知道历史请求的完整参考范围。
