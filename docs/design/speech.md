# 候选译词按需朗读

个人修改版面向 Windows 与安卓手机，支持同局域网或临时公网 HTTPS 连接。中文候选的英文译词、英文候选本身提供小喇叭，用户点击或按朗读组合键才朗读该行英文；不自动朗读上屏，不改变原来的选词与译词上屏手势。

## 职责与边界

- Core 的 `Candidate::speech_text` 对 `English` 候选取单词本身，其余候选由 `Translation::speech_text` 提供纯英文义项，去掉空项、重复项，不含词性、注音与生词标记。
- 渲染帧 `Row::speakable` 表示有朗读操作；annotation 正文列末尾画矢量喇叭，英文候选没有释义也保留入口，词性单独成列的主题不重复画按钮。产生独立 `HitTarget::Speak`，命中优先于译词与候选。Windows 使用 Core 的正文判断，其他平台默认关闭。
- Router 朗读分支不调用 commit、不消费拼音、不记学习；发送到 `SpeechSink` 后保留候选。没有连接工具时显示设置提示。
- Windows 的 `[shortcut] speak_candidate` 为可关闭的修饰键配置，加当前页序号 `1`～`9` 复用点击发送分支，不上屏或改高亮；空闲态不截键，页外序号不发送。默认关闭，与译词上屏或删除键冲突时不启用；设置支持录键及 Backspace 清除。
- 朗读分支在鼠标上屏的 DLL 协议检查前处理，旧版会话也能发送；鼠标上屏仍要求协议 8。后台结果只更新尚未被下一次输入清除的发送中提示，不把连接工具接受等同于手机播放。
- Windows 在缓存的原图上由渲染器叠加喇叭悬停 / 按下反馈，手形光标与捕获由壳管理；同一喇叭上松开发送、拖出取消，候选变化或隐藏也取消按下状态。
- `SpeechSender` 使用有界后台队列；连接文件只接受端口与随机令牌，目的地址固定回环。输入/UI 线程不等待网络。
- `tools/speech-relay` 是独立 Python 标准库工具。手机用接收令牌读取最新点击；发布额外限制回环来源与独立发布令牌，不记录词条历史，不捕获键盘或剪贴板。接收凭证不能用于发布，即使隧道代理将请求转成回环来源也不例外。
- `--internet` 额外启动用户安装的官方 `cloudflared` Quick Tunnel，HTTP 服务只监听回环；手机通过随机 HTTPS 域名接收。只管理本次子进程，关闭时停止子进程并清除本次连接文件，不改系统服务或防火墙。

## 用户流程与限制

电脑启动工具 → 复制配对地址到手机 → 手机连耳机并启用朗读 → 点击候选旁喇叭。手机页面须保持前台，后台/锁屏停止接收；首版不承诺后台长期运行。语音联网与否由手机语音引擎决定。局域网 HTTP 只用于受信任专用网络，不自动开放防火墙或公网端口。

不同局域网时用 `start.ps1 -Internet` 启动，手机可使用移动网络。接收页使用长轮询，兼容不支持 SSE 的 Quick Tunnel。英文经 Cloudflare 中转，TLS 在其边缘终止，非端到端加密。临时隧道没有可用性保证，重启后重新配对；不当作固定地址或后台服务。发布凭证不嵌入网页、不经隧道发送，现有 Rust 发送器每次读取连接文件即可使用，无需改变回环发送协议。

重复点击允许重听；等待中的旧请求被新请求替换，手机收到新词时取消旧发声。重新启用不重播旧事件。端点与连接文件见 [工具说明](../../tools/speech-relay/README.md)。

## 验收

二维码在配对页客户端用随包 MIT qrcode-generator 1.4.4 生成，不将完整地址交给第三方 QR 接口。Android 0.1.1 使用 ZXing Android Embedded 4.3.0 内置相机扫描，通过 Activity Result API 返回同一 `Pairing.parse` 校验路径，验证后才保存地址并启动服务。仅二维码模式，不外跳浏览器；取消与无效输入保留旧地址，相机权限只在扫码时请求。自动化测试使用网页相同生成器产出的模块矩阵，经安卓 ZXing 解码再校验地址完整性。

Tailscale 模式使用 Serve 的专用 HTTPS 端口 8443 代理回环服务，不启用 Funnel；启动前检查同端口已有路由，拒绝覆盖其他服务或复用已公开的端口。`pairing.json` 保存互相独立的接收 / 发布凭证及最后事件序号，不保存正文；每次发布先原子保存序号，失败则返回 503。配对损坏须显式重置。持久事件序号保证现有 Android 长轮询客户端在工具重启后继续接收，无需修改客户端协议。

`apps/android-speech` 为独立原生 Android 接收端，使用随 APK 提供的 KittenTTS nano 英文模型与 sherpa-onnx，不依赖系统 TTS 设置。用户主动启动 specialUse / mediaPlayback 前台服务；HTTPS 长轮询与单槽生成任务分开，音频以媒体语音属性播放，短暂 MAY_DUCK 音频焦点仅在播放期间持有。PCM 做 RMS 归一化、用户增益与软限幅。会话唤醒锁停止即释放；Doze 的网络限制仍需设备设置和锁屏实测，不承诺无限后台存活。

核心测试覆盖英文正文、词性/注音剥离、重复义项与非英文；渲染测试覆盖深浅色、横竖排、DPI 和独立命中；Router 测试验证无上屏、拼音/候选保持与重复点击；发送器验证回环 HTTP 鉴权及正文；接收工具验证鉴权、来源、大小与最新事件。

修改版仍须在真实 Windows 应用中验证点击不失焦、候选保持、原选词功能正常，并用安卓手机与耳机确认发声。编译通过不等于真机验收通过。
