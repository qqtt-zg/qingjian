# 手机学习与 AI 答疑

## 目标与阶段

围绕用户实际输入的英文建立学习记录，手机离开电脑后仍可复习；联网时可独立向配置的 AI 服务提问。0.2.3-dev 起首页采用「今日、词汇、复习、设置」四个入口；`MainActivity` 是统一设置页，合并接收、扫码、声音、AI 配置、应用更新和数据管理。页面切换只控制界面，不负责启动或停止接收服务。原「我的」不再单独渲染，避免两套设置入口。

0.2.4-dev 为两层页面指定不重叠的职责：设置首页只负责扫码、连接、停止和只读的音色/音量摘要；`SpeechSettingsActivity` 只负责声音编辑、试听、后台、诊断及手动地址保存。子页不显示连接状态或启停操作，保存地址不立即连接；返回首页后主动连接生效。音量滑块、预设和试听不在首页重复出现，「朗读设置」只有一个可见入口。

子页复用 `MainActivity` 的控制逻辑而不复制接收或播放器。「数据与关于」承载记录清空、版本和许可说明。清空记录后回到学习页时，同时清除指向已删除词汇的本轮复习状态。更新摘要由设置页的前台刷新同步，AI 摘要只表明配置已保存，不冒充连接测试结果。

统一设置页可能只用于查看 AI 或应用选项，不能在进入页面时请求朗读通知权限；权限请求推迟到主动连接或试听操作。

0.2.5-dev 将语速以 `speech.rate_percent` 整数保存，50～200、步长 5、缺省 100；`SpeechPlayer` 每次合成读取并传给 sherpa-onnx 的 `generate`，不修改 AudioTrack 采样率，也不在当前播放中途切换。现有 Kokoro 和 Kitten 模型使用同一入口，原短词缓冲区补静音逻辑保留。官方版本依据为 [sherpa-onnx v1.13.8 Kitten](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-tts-kitten-impl.h) 与 [Kokoro](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-tts-kokoro-impl.h)。

子页通过 `Views.header/page` 共用原生 Toolbar 和主题提供的返回图标，保留“返回”无障碍标签，点击仍执行当前 Activity 的 finish。朗读子页隐藏原 XML 的重复标题；扫码页原有关闭图标保留。

0.2.8-dev 增加 `WordStudyActivity` 词汇学习详情，复用该词的 `word:<id>` 会话。`StudyDirection` 提供词性用法、搭配例句、常见错误和自定义双词辨析的问题草稿；辨析可带用户主动填写的句子或中文意图。选择方向只向 `TutorActivity` 传入草稿，明确点发送才调用 API。返回后保留对比词和语境草稿，已保存讲解从原会话读取，离线可看完整历史；不增加数据库版本或自动生成词义、成绩，不声称已实现结构化资料包与正式测验。

0.2.9-dev 在同一学习流程加入离线笔记测验与录音跟读。`quiz/Builder` 从用户笔记生成最多五题，选择题至少两个不同选项，拼写跳过同笔记多词歧义；`Question` 固定英文、笔记与选项快照。唯一题目标识在数据库去重，页面重建从已保存答案恢复，错题只看该词该题型最新作答，累计历史保持。测验、卡片自评、录音自评各自记录。

`oral/Recorder` 仅在用户点击且授予麦克风权限后通过 AudioRecord 录制 16 kHz 单声道 PCM16 WAV，最多 30 秒，离页或音频焦点丢失即取消并释放。文件先在私有缓存，明确保存后移动到私有 files/oral；MediaPlayer 回放，用户可独立自评或删除。当前用户没有发音评估账号，已明确选择先实现录音与自评；无录音上传、无假分数，数据结构保留原始音频和参考英文供将来服务接入。API 依据为 [AudioRecord](https://developer.android.com/reference/android/media/AudioRecord) 与 [运行时权限](https://developer.android.com/training/permissions/requesting)。

0.2.0-dev 是第一个可安装阶段：

- 收录电脑收到的英文；收到次数与完整播放次数分开，不将播放计为掌握。
- 本机词汇、中文笔记、最多五词的卡片自评；自评次数单独计数。
- 自定义 HTTPS 地址、模型 ID、用户提供的 API Key；兼容 Chat Completions，包含非流式文本回答与连接测试。
- 当前词汇、笔记及有限会话历史辅助答疑；问题先保存，回答可离线阅读。
- 网络或配置错误后保留问题，仅由用户手动重试；不自动发起可能收费的后台请求。

后续阶段保持以下目标，当前不对外声称已实现：

1. 电脑发送中文原词、相关候选与主动提供的句子语境；生成辨析、搭配、例句和练习资料包。
2. 每日与周六总结的持久队列、资料包下载确认、跨电脑同步及复习调度。
3. 客观题与拼写测验、错题与不同能力的独立统计。
4. 手机录音和口语测验；专门的发音评估后端及逐词反馈。无后端时显示待评估，不生成分数。

## 本地存储

此前调研的复用候选包括 [AnkiDroid API](https://github.com/ankidroid/Anki-Android/wiki/AnkiDroid-API)（把词卡交给独立 App）、[ForgetMeNot](https://github.com/tema6120/ForgetMeNot)（完整学习 App，可参考或迁移练习流程）、[FSRS-Kotlin](https://github.com/open-spaced-repetition/FSRS-Kotlin)（复习调度算法源码候选）。当前实现未引入这三个项目的代码，也没有 FSRS 调度；基础笔记测验和录音使用本机原生能力。以后加入遗忘曲线时优先评估成熟算法，仍需核验实现与测试，不能将示例仓库等同于完整学习模块。

`apps/android-speech` 仍为 Kotlin 原生界面。第一阶段不新增依赖，使用 `LearningStore` 封装系统 SQLite；将来采用 Room 时迁移数据库，保持已有词汇与对话，不以清库代替迁移。当前版本不是完整的 MVVM/Room 重构。

`learning.db` 中 `words` 保存英文、用户中文笔记、收到次数、完整播放次数、自评复习次数及最后时间；`messages` 按通用或词汇主题分隔会话，记录待回答、失败与已回答状态。列表显示最近 500 词，会话显示最近 100 条；请求只取最近已完成的至多 12 条会话，并限制总长度。当前尚无 FSRS 调度或自动词义生成。

0.2.9-dev 将数据库从 v1 迁移到 v2，只增加 `quiz_attempts` 与 `oral_recordings`，保留 words/messages 和全部原计数。`PracticeStore` 以 question_key 唯一约束防止重复计分，拒绝对已删除或已替换词汇写入成绩。录音文件名只接受应用生成的 UUID，清空学习资料同时删除所属录音文件，配对、声音与密钥配置保留。云备份与设备迁移继续排除数据库、偏好和私有文件。

英文只在实际收到且允许播放时增加收到次数；播放器确认完整输出后增加播放次数。被新请求替换、焦点拒绝、播放中断和超时不增加播放次数；内置离线试听不写入词汇。原协议只有英文，不能据此推断原中文或用户真正想表达的句子。

## AI 请求边界

0.2.6-dev 的 AI 配置页将保存提示与连接测试结果分开；测试区域自动滚动可见，包含 ProgressBar、阶段、单调时钟计时和取消操作。测试期间锁定配置字段与保存/清除按钮，修改字段后使旧结果失效。只有收到可解析的非空文本才显示成功；错误保留受控说明和 HTTP 状态。离开或重建页面会取消请求，不自动重试；重建提示上一次测试中断，不把密钥放入实例状态。

服务使用用户提供的 HTTPS Chat Completions 地址，不需要公司电脑在线，不复用配对凭证或静默读取桌面密钥。地址支持填写基础路径或完整 `/chat/completions`；拒绝 HTTP、URL 账号、查询参数和片段，拒绝跟随重定向。此阶段没有 Responses/Anthropic 原生协议适配，也没有音频评估协议。

密钥通过 Android Keystore AES-GCM 加密，偏好中仅保存密文和 IV；禁止备份/设备迁移学习数据库和偏好，密钥输入页禁止截屏和保存输入控件状态。错误只展示自定义说明和 HTTP 状态，不回显服务商错误正文、密钥或请求体。回答按 TextView 纯文字显示，不执行 HTML、链接脚本或模型工具调用。

教学规则指导模型先回答当前疑问，再给少量例句与练习；语境不足先询问；不得宣称已评估未提供的录音。提示词无法保证语言事实完全正确，UI 明确标明 AI 回答可能有误。真实成绩、复习状态与设置仍由应用代码管理，模型不能自行写入。

## 验证

0.2.10-dev 将下载传输独立为 `update/PackageDownload`：按 4 MiB 区间读取，只接受匹配的 Content-Range/长度，不把续传的 HTTP 200 整包误追加。文件按完整 SHA-256 标识，中断/暂停保留 .part，暂时连接错误最多连续重试三次、总恢复次数有上限；最终仍重算全包 SHA、检查真实包版本/签名。区分网络、存储、配对、协议和完整性错误，不将任意异常都归为签名问题。旧服务只支持从零完整下载，续传会明确要求更新电脑工具。更新页支持暂停/继续/从头下载与大小/速度反馈。

电脑 `update_http.py` 对已鉴权哈希文件支持单区间 Range、If-Range、HEAD、206/416，不公开任意文件；旧不可变哈希保留时允许进行中的下载跨越新版本发布继续。`transfer` 探针验证超时后准确偏移续传、暂停和重复中断保留、错误范围拒绝、旧服务兼容及损坏数据丢弃；`download_ui` 用真实签名 APK 驱动暂停/继续按钮并确认最终验证。电脑端 24 项相关隔离测试与原 `updates` 探针通过。

0.2.7-dev 将更新缓存从固定 `update.apk` 改为 SHA-256 命名的独立文件和 FileProvider URI；检查到不同包/构建时移除旧 ready 标记，安装前校验失败也清除此标记以恢复下载。更新页显示目标版本，并提供重新下载入口。旧固定文件不作为新版本可安装的依据。`UpdateProbe` 覆盖遗留缓存、不同元数据、篡改缓存恢复、确切安装文件与系统安装入口。

`SmokeInstrumentation -e learning true` 仅用于无个人数据的隔离模拟器：验证数据库计数/搜索/会话隔离，Keystore 往返与偏好无明文密钥，HTTPS 校验、请求体、响应解析、重定向拒绝、HTTP 429 和取消，以及原生导航、卡片自评与离线问题保存。受控连接仅替代测试中的传输，不修改生产 TLS 信任或明文策略。

`-e ai_connection true` 同样只在隔离模拟器使用虚构凭证，驱动真实 AI 配置页面，验证等待动画/计时、成功可见、HTTP 401、取消、输入校验、字段修改失效和保存不覆盖结果。

`-e study true` 在无个人数据的隔离模拟器驱动词汇卡片、学习详情与答疑：验证问题模板边界、无自动网络请求、显式发送、按词保存回答、语境辨析、返回草稿保留、清除配置后离线回看。

0.2.8-dev 已通过 `study` 与原 `learning` 回归，并在模拟器检查学习详情的实际布局。用户手机从构建 12 更新时提示“版本相同”的原因尚未确认；之前的更新测试仅验证下载/校验与安装入口，不代表真机完成安装。用户同意将该完整链路留到下一版真机验证，本次不继续调整更新流程。

0.2.9-dev 已在隔离 Android 16 模拟器通过 `migration/practice/quiz/oral/learning/study/settings`：包括 v1 保留迁移、重复提交去重、错题恢复、页面重建、无权限拒录、实际 AudioRecord WAV、MediaPlayer 回放、离页取消和实际 30 秒自动停止。Android lint 为零错误，仍有现有界面硬编码等警告；已检查复习页和录音页实际布局。测试未在用户手机执行，也未调用真实 AI 或发音评估服务。

真实服务商的协议、计费、可达性和回答质量需要用户配置后点测试连接确认；测试数据不能证明所有中转站兼容。原音色与播放测试仍独立运行。
