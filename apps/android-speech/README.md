# 青简 Android 学习与朗读（个人试用版）

当前个人版 0.2.10-dev 支持本机英文记录、中文笔记、离线卡片自评、自定义 AI API 与词汇答疑。底部为「今日、词汇、复习、设置」四个标签，原「朗读」与「我的」合并为统一设置页，集中处理连接、声音、AI、应用更新及数据管理。使用说明见 [手机词汇与 AI 答疑](../../docs/user/learning/mobile.md)。自动总结、AI 语境出题与自动发音评分尚未接入。

更新支持分段下载、暂停和断点续传，显示已下载大小与速度；中断后保留进度，网络错误与签名错误分别提示。电脑连接工具需要同时更新才能续传。

「复习」增加离线词义选择、中文拼写和错题重测，成绩按题型分别记录。词汇学习与复习中可录音跟读、保存回放和自评；录音仅留在手机，每段最多 30 秒，当前不自动评估发音。

词汇卡片的「学习这个词」提供词性用法、搭配例句、常见错误及带语境的相近词辨析，先准备问题草稿，确认后才发送。已保存讲解可在学习详情离线回看。

更新页显示目标版本和构建号；下载完成后也可重新下载安装包。不同版本使用独立缓存，旧固定缓存和校验失败的包不作为可安装依据。

构建 16 已在隔离 Android 16 模拟器通过更新回归：遗留缓存、目标包变化、篡改后重新下载、重新下载按钮、签名/哈希检查、FileProvider 和系统安装 Intent；候选使用真实同签名 APK，未在用户手机上执行安装。

AI 设置的连接测试显示加载动画、请求阶段与已等待秒数，可取消；结束后保留成功/失败、耗时与错误说明，保存配置不覆盖结果。构建 15 已在独立 Android 16 模拟器通过 `-e ai_connection true`（受控成功/HTTP 401/取消、等待计时、可见性、保存与字段校验）及 `-e learning true` 回归测试，未访问真实 AI 服务。

朗读设置支持 0.50×～2.00× 的语速调节，默认正常语速，保存后从下一条试听或接收朗读生效。各子页统一采用原生顶部返回箭头，替代大号文字返回按钮。

设置首页只提供扫码、连接和停止接收，并显示音色、音量摘要；只有一个「朗读设置」入口。音色选择、试听、音量滑块/预设、手动配对地址、后台与诊断只在该子页显示，手动地址保存后回首页连接。「设置 → 数据与关于」管理学习记录、版本和许可，避免将清空操作放在常用入口旁。子页与首页共用偏好，返回后同步摘要。

Android 8 及以上，交付包为 ARM64，适合一加 Ace 5。0.1.5 内置 Kokoro 1.0 的 af_heart 美式女声、KittenTTS nano 0.1 的其他七个音色及 sherpa-onnx 1.13.8；无需修改手机系统 TTS。电脑使用本仓库修改版，在「青简设置 → 手机朗读」中启动连接；也保留 `tools/speech-relay/start.ps1 -Internet` 命令行入口。

长期个人使用可改为 `tools/speech-relay/start.ps1 -Tailscale`。电脑与手机安装并登录同一 Tailscale 网络，将首次显示的固定 HTTPS 完整地址粘贴到本 App；此模式持久保存配对凭证，工具重启后可复用。App 无需更换，仍需主动开启接收，并保持手机 Tailscale 在线。首次 HTTPS / Serve 启用与设备密钥有效期见 `tools/speech-relay/README.md`。

## 安装与使用

**0.1.5 内置 af_heart**：覆盖安装后，在手机选择「女声 1 · af_heart」即可离线试播；电脑已有的「内置 · 女声 1」也会使用它，不需要发送模型文件夹。新安装默认选中该音色，覆盖安装保留选择。其他七个选择仍使用原 Kitten 模型。Kitten 与 Kokoro 切换时分别加载相应模型，首次准备稍慢，状态会提示。

af_heart 需要完整 Kokoro 推理模型及英文发音数据；因此 APK 显著大于原来的约 65 MB。随包只保留 Kokoro 模型、音色数据、英文词典、eSpeak 数据及许可，不包含官方辅助脚本和其他语言词典；模型与私有副本还会占用安装后的存储空间。预留至少 1.5 GB 可用空间供安装和首次准备，首次无需联网下载模型。

0.1.4 起推荐从电脑的「青简设置 → 手机朗读」集中操作：启动连接、扫码、启停朗读、选择音色、试听及发送模型文件夹。手机 App 需先更新到 0.1.4 一次，之后兼容 Kitten / Piper(VITS) / Kokoro 模型可动态传输和加载，无需重新打包 APK。完整传输已用约 30 MB 的真实 Kitten 数据包验证；新模型仍须与内置 sherpa-onnx 1.13.8 兼容。

音色包通过带配对鉴权的 HTTPS 下载，先检查大小与 SHA-256，再在应用私有暂存目录受限解压、原子安装。动态加载与合成使用同一工作线程；失败保留当前音色或恢复内置音色。手机回报安装进度及模型可用音色数，电脑列表会刷新；APK 内仍保留默认离线音色。未经电脑端选择的包不会主动下载。

1. 把 APK 发到手机，点击安装。本版本为调试签名的个人测试包。
2. 打开「青简朗读」，允许通知。先点「离线试播英文」，连接蓝牙耳机确认声音正常。
3. 在 App 点击「扫码连接」，首次使用允许相机权限，对准电脑配对页二维码；识别后自动保存 HTTPS 地址并启动接收。也可粘贴完整地址后点「连接并在后台接收」。无需同时启用浏览器接收页，否则可能重复播放。
4. 显示「已连接」后可切换应用或锁屏，在电脑点击喇叭。通知栏「停止」可结束接收；App 里也可停止。不会开机自动启动。
5. 英文音色可选 8 种（4 男、4 女），选择后点「离线试播英文」比较，后续朗读使用保存的音色。朗读音量增强可调 50%～400%，音量键控制系统媒体音量。应用对语音进行响度归一化和软限幅，朗读前请求短暂音频焦点，结束或取消后释放，让支持的音乐应用恢复音量。其他应用也可能选择暂停。

首次使用相应内置模型时会将音色复制到应用私有目录，无需联网下载。网络用于接收电脑点击的英文、控制指令及主动选择的模型包，并向已配对电脑回报状态和音色列表；配对地址存于应用私有偏好，禁止系统备份。0.2.0-dev 起会在本机保存词汇和用户主动发送的 AI 问答；文字答疑直接发送给用户配置的 AI 服务，不要求电脑在线。Kokoro 英文模型与配套数据约 378 MB，另有 Kitten、原生库和模型私有副本。

锁屏持续联网仍受 Android Doze 和厂商省电管理影响。若一加系统限制后台，请通过「后台省电设置」允许本应用后台运行，并实测长时间锁屏；前台服务与会话唤醒锁不等于无条件绕过 Doze。只在用户主动开启接收期间维持服务和唤醒锁，停止即释放。

公网链接变化后重新粘贴；HTTP 地址不接受，HTTPS 重定向不携带凭证跟随。现有局域网 HTTP 网页方式仍可继续使用。

0.1.1 增加 App 内扫码连接，可直接覆盖安装 0.1.0。电脑工具重启后重新扫描新二维码；只重开 App 时可点连接复用保存的地址。二维码由本机自带的 JavaScript 库生成，相机解码使用内置 ZXing，无需 Google Play 服务或联网下载扫码模型。相机仅在扫码页打开期间使用；取消、权限未授予或内容无效时保留原地址。扫码内容须通过与粘贴相同的 HTTPS 配对校验，不打开二维码指向的浏览器页面，不执行其他内容。

扫码依赖固定为 ZXing Android Embedded 4.3.0 / ZXing Core 3.4.1，AndroidX Activity 1.9.3，均为 Apache-2.0；可在 App 的许可与来源页查看出处。除语音与扫描相关原生库外，不需要安装外部扫码 App。

## 构建

0.1.2 开放模型已有的八个音色，无需额外下载；上游 ID 0/2/4/6 为男声，1/3/5/7 为女声，界面按男声 1、女声 1……显示。语音生成前读取保存的选项，不切换手机系统默认音色。增强上限从 200% 提至 400%，并放宽极低振幅输入的归一化增益限制，最终仍软限幅到 PCM 范围。原有音量设置保留，不会在升级时自动调高。模拟器对同一句话八音色测得 400% 的 PCM RMS 高于 200%；这不是一加手机或蓝牙耳机的声压测量，不保证达到其他应用的主观响度。

需要 Python 3.12+、JDK 17、Gradle 8.13、Android SDK 36（Build Tools 36）。官方 AAR 与模型 URL/SHA-256 记录在 `dependencies.json`，二进制和音色不入 Git。首次构建：

```powershell
pwsh -File .\apps\android-speech\build.ps1 -Prepare
```

本机已有依赖时可省略 `-Prepare`。输出 `app/build/outputs/apk/debug/app-debug.apk`。`-Abi x86_64` 仅用于模拟器。源代码依照仓库 GPL-3.0；模型为 Apache-2.0，原生依赖及数据的第三方说明位于 APK assets 中的 `THIRD-PARTY.txt`，App 内可以查看来源。

## 验证边界

0.2.5-dev 在全新隔离模拟器通过 `toolbar`、`settings`、`learning`、`rate` 和 `short_audio` 探针：五个子页的原生返回箭头可用，语速保存及摘要同步正常；真实 Kokoro/Kitten 在 0.75/1.0/1.5 倍下的音频样本数分别单调减少，短词流缓冲区播放与学习计数回归通过。没有清空可见模拟器或真实手机的数据。真实手机上的听感仍需覆盖安装后确认。

0.2.4-dev 的设置探针在隔离模拟器验证两层可见控件不重叠：主页无音量滑块和试听，子页无扫码/停止及连接状态；子页地址按钮只保存，返回后声音摘要同步。原学习导航与答疑探针也通过。

0.2.3-dev 的四入口统一设置页已在隔离模拟器验证：原朗读和「我的」选项位于同一页，子页声音偏好返回同步，清空资料后复习状态重置，切回学习保持本轮进度。未授予通知权限时，单纯打开设置不会弹出权限请求；仅在主动连接或试听时申请。设置与学习探针均通过。

0.2.2-dev 的 `settings` 探针在隔离模拟器通过：主页隐藏手动地址、音色选择器和诊断，更多设置中可见；更改声音选项后返回主页同步显示；数据与关于独立展示，清空记录后本轮复习状态重置。原学习导航与答疑探针也通过。未使用真实手机或用户 API 密钥进行这些测试。

0.2.1-dev 的五标签导航已在隔离模拟器验证：学习页直接打开朗读页，朗读页保留底部导航，返回「我的」可见 AI 配置和应用更新，再回到「复习」保留本轮进度。ARM64 包与此前个人版本签名一致，切换标签不会主动启停朗读服务。

0.2.0-dev 的第一阶段已在新建的隔离 Android 16 x86_64 模拟器验证：本机词汇/复习/会话、Keystore 加密与 HTTPS 校验、受控 Chat Completions 请求/解析/跳转拒绝/限流/取消、异步答疑单请求与持久化、原生四入口及离线问题保存。使用假密钥和测试连接，没有调用用户的真实服务商。短词测试同时验证 af_heart 的 `control`、`control system` 真实流播放进度，以及每次完整播放恰好增加一次本机播放记录。ARM64 包编译、ABI 与签名检查通过；真实中转站与一加手机仍需填写配置和覆盖安装后确认。

0.1.6 修复短词无法达到 `MODE_STREAM` 起播门槛的问题：按实际缓冲区 / 起播阈值给短音频补末尾静音，先写入缓冲区再启动；播放进度未完成时明确显示超时，不再误报完成。模型、音色映射和语速不变。`-e short_audio true` 用内置 af_heart 合成 `control` / `control system`，以两秒的真实 AudioTrack 缓冲区验证播放进度确实前进；旧版在这个受控条件下会对 `control` 误报完成。Android 的起播要求见 [AudioTrack.play](https://developer.android.com/reference/android/media/AudioTrack#play())。实体手机和蓝牙耳机仍需覆盖安装后确认听感。

`-e heart true` 验证 af_heart 的上游 speaker ID 3、首次默认选择、I / hello / water / develop 短词非静音合成，以及 Kitten → Kokoro → Kitten → Kokoro 真实播放。此探针只使用 APK 内置数据，不需要电脑下载接口或公网配对。

0.1.5 已在隔离 Android 16 x86_64 模拟器通过上述探针与普通烟测（扫码解码 / 配对校验、音色保存、PCM 增益、前台播放及清理）。交付 ARM64 包已检查架构、签名和内置模型哈希，约 434 MB（414 MiB）；实体手机的首次加载时间、蓝牙听感与锁屏接收仍需实际使用确认。

0.1.3 增加“最近接收”和“最近朗读”：前者记录最近一次网络请求的时间与序号，后者保留当前音色的合成、播放、失败或中断提示；不保存英文正文或配对地址到这些诊断字段。离线试听结束后，即使服务停止，也保留最后音频状态，避免失败原因被“已停止”覆盖。旧音频焦点回调仅能取消对应请求，不再递增序号误取消新点击。空 / 无效合成结果明确显示合成失败。

`-e playback true` 设备测试逐个让八音色走实际 SpeechPlayer 与音频焦点流程。此测试在模拟器中通过；如某手机只有部分音色有声，请先用同一离线试播句比较，再查看两项诊断，区分网络未收到、合成失败或播放被打断。不能据模拟器结果断言所有机型均正常。

进一步的设备探针：`-e network <隔离测试服务的完整HTTPS地址>` 在已启动的测试服务每五秒发送合成测试句时，验证八音色网络接收与播放，以及已连接会话中插入离线试播后仍继续接收；`-e words true` 测量八音色的 I、hello、me、water、develop 短词合成。两者均在模拟器通过。测试应使用隔离服务，避免给实际用户接收端播放测试词；这些结果不代表已复现或修复某一手机的接收问题。

设备侧 `SmokeInstrumentation` 覆盖真实离线模型生成非静音 PCM、增益范围、配对地址拒绝与前台音频播放后停止清理。模拟器通过不替代一加 Ace 5 的锁屏网络、蓝牙路由、听感和其他应用降低音量测试。

## 通过已配对电脑更新 App

构建 9 起支持应用内更新，当前入口为「设置 → 应用更新」。连接成功后自动检查；手动点击下载、安装。下载沿用 HTTPS 和手机配对鉴权，拒绝跳转，校验大小 / SHA-256 / 包名 / 更高 versionCode / 当前安装签名。安装前再次校验，通过仅开放更新缓存目录的 FileProvider 交给系统安装器；首次需允许本应用安装未知应用。覆盖安装保留学习数据；初次加入此功能仍需手动安装一次。

在仓库根目录执行 `pwsh -File apps/android-speech/build.ps1 -PublishUpdate`，构建 ARM64 APK 并发布至本机 `%APPDATA%\Qingjian\speech\updates`。正常构建不发布；模拟器包不能发布。每次更新递增 `app/build.gradle` 的 versionCode，并保留相同签名密钥。保持电脑连接工具在线，手机检查即可获取，无需重新扫码（原配对仍有效时）。电脑旧进程需更新工具并重启一次。指定了独立 state-file 的服务须用 `app_updates.py --root <对应目录/updates>` 发布。

0.2.10-dev 起支持暂停、继续和网络中断后断点续传，需电脑连接工具同时支持分段下载；旧工具可以从零完整下载，但无法从中间继续。下载完成仍会校验完整包的哈希、版本和签名。音色仍随完整 APK 分发，所以更新包较大。测试探针 `-e updates true` 只允许在隔离模拟器使用：预先把同签名、版本高一个构建的真实 APK 放到应用外部 files/candidate.apk，探针用受控 HTTPS 响应验证下载、哈希拒绝、包名/版本与签名检查、FileProvider 和更新页；不访问真实配对服务。

构建 9 验证：电脑端 33 项隔离测试通过；Android lintDebug 无错误，ARM64 APK 的包名 / 构建号 / ABI / 签名校验通过。新建 Android 16 x86_64 隔离模拟器上，以构建 8 为基线、构建 9 的真实同签名 ARM64 APK 为候选，验证版本检查、完整下载、哈希篡改拒绝、签名包解析、FileProvider 读取、更新页和系统安装 Intent 调用（拦截安装，不执行 ARM64 包安装），以及旧服务和跳转拒绝。真实电脑隧道下载与一加手机系统安装确认仍需真机验证。
